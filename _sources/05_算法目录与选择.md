# 算法目录与选择

| 通用 | `SPEA2` | `SPEA2` | 强度适应度与距离截断 |
| 约束 | `BiCo` | `BiCo` | 双种群约束协同 |
| 约束 | `CMOEAD` | `CMOEAD` | 约束分解式优化 |
| 约束 | `CCMO` | `CCMO` | 双种群约束优化 |
| 约束 | `CMEGL` | `CMEGL` | 全局与局部信息结合 |
| 约束 | `CMOEACD` | `CMOEACD` | 分解与约束支配 |
| 约束 | `CMOEAMS` | `CMOEAMS` | 多阶段约束处理 |

算法可直接导入：

```python
from ascendmoea.algorithms import CMMO, MOEAPSL, NSGAII
```

也可由注册名创建：

```python
from ascendmoea import create_algorithm

algorithm = create_algorithm("MOEA-PSL", save=20)
```

## 选择算法的依据

### 根据问题特征筛选

- 约束值全部为空或恒为零：先用 `NSGAII`、`MOEAD` 或 `SPEA2` 建立基线。
- 可行域狭窄或不连续：选择约束算法，并同时报告可行率。
- 同一目标向量对应多个差异显著的决策解：使用多模态算法，并评价 IGDX 或 PSP。
- 决策维度高且最优解仅激活少量变量：使用稀疏算法，并记录掩码密度。

### 结合计算结构判断

NPU 适合有大规模矩阵比较、距离计算和批量评价的算法。若算法每代只处理很小种群，或
存在大量依赖数据的 Python 分支，设备调度开销可能高于并行收益。选择算法时应把求解
质量与目标硬件上的吞吐同时纳入实验。

## `save` 参数

所有算法继承 `Algorithm(save=...)`。`abs(save)` 控制算法自身 `result` 中最多保留的
均匀进度历史槽位，`save=0` 与 `save=1` 都保留最新槽位，
不等同于精确保存每一代：

- `save=1`：仅保证最终记录；
- `save=20` 或 `save=-20`：按评价进度最多保留 20 个槽位；
- 需要每代完整种群：使用 `HistoryMonitor` 或流式监控器。

正式实验不要依赖有限的 `result` 槽位替代完整历史。

## 兼容性检查

算法和问题组合至少应满足：

1. 问题编码是算法算子支持的类型；
2. 目标数满足参考向量或环境选择要求；
3. 种群规模足以生成所需参考向量或父代分组；
4. `max_fe` 至少容纳初始化和一个完整后代批次；
5. 约束算法得到形状稳定的 `[N, C]` 约束张量。

快速试运行可用较小预算。需要分析算法质量时，应采用与问题规模匹配的设置，例如
`N=100`、`max_fe=10_000` 或更高，并使用多个随机种子。

## 自检与配置驱动运行

```python
from ascendmoea import get_algorithm, list_algorithms

for name in list_algorithms():
    cls = get_algorithm(name)
    print(name, cls.__module__, cls.__name__)
```

配置文件应保存注册名、构造参数和源码版本。不要只保存类名字符串，因为注册名是面向
实验配置的稳定标识。
