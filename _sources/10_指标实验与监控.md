# 指标实验与监控

## 指标入口

```python
from ascendmoea.metrics import (
    coverage_rate,
    cpf,
    delta_p,
    dm,
    feasible_rate,
    gd,
    hv,
    igd,
    igdp,
    igdx,
    psp,
)
```

| 指标 | 优化方向 | 所需参考数据 | 适用重点 |
|---|---|---|---|
| HV | 越大越好 | 目标空间参考前沿/归一化范围 | 收敛与分布综合表现 |
| IGD | 越小越好 | 目标空间参考点 | 参考前沿覆盖 |
| IGD+ | 越小越好 | 目标空间参考点 | 支配感知距离 |
| GD | 越小越好 | 目标空间参考点 | 解集到前沿距离 |
| DeltaP | 越小越好 | 目标空间参考点 | 双向距离平衡 |
| DM | 越大越好 | 目标空间参考点 | 网格多样性 |
| CPF | 越大越好 | 目标空间参考点 | 前沿流形覆盖 |
| IGDX | 越小越好 | 决策空间参考 Pareto 集 | 多模态决策解质量 |
| CR | 越大越好 | 决策空间参考 Pareto 集 | 决策范围覆盖 |
| PSP | 越小越好 | 决策空间参考 Pareto 集 | 距离与覆盖综合评价 |
| Feasible rate | 越大越好 | 无 | 约束可行率 |

高于三目标的 HV 使用蒙特卡洛估计。正式统计必须固定随机种子、样本数和归一化规则；
若需要完全确定的高维 HV，应在实验外接入确定性实现并记录其版本。

## 每代指标

```python
from ascendmoea import HistoryMonitor, optimize
from ascendmoea.metrics import hv, igd

history = HistoryMonitor(copy_to_cpu=True)
result = optimize(algorithm, problem, monitors=history, device="cpu", seed=1)
reference = problem.optimum.detach().cpu()

rows = []
for record in history.records:
    rows.append(
        {
            "fe": record.evaluations,
            "hv": hv(record.population, reference),
            "igd": igd(record.population, reference),
        }
    )
```

`HistoryMonitor` 会把所有种群留在内存中，只适合调试或中小规模任务。正式全量实验应
编写流式 `Monitor`：每次回调将 `decs`、`objs`、`cons`、FE 和时间戳写入单独文件，
先写临时文件，再原子重命名，最后更新进度 JSON。

## 推荐结果目录

```text
results/
  <stage>/<device>/<algorithm>/<problem>/seed_<seed>/
    config.json
    environment.json
    progress.json
    generations/
      fe_00000100.npz
      fe_00000200.npz
    metrics.csv
    summary.json
    resource_samples.csv
    COMPLETE
```

`COMPLETE` 只能在所有数据成功落盘、摘要可读取且校验完成后创建。失败任务保留错误日志，
重跑时写入新版本目录，不覆盖可追溯的旧结果。

## 内存记录

### 主机内存

建议每 0.2 至 1 秒采样一次进程树的 RSS 和 PSS：

- RSS 易获得，但共享库会在多进程求和时重复统计；
- PSS 按共享比例分摊，更适合报告多 worker 总占用；
- 同时记录整机 available memory、swap 和 OOM 事件。

Linux 可从 `/proc/<pid>/smaps_rollup` 读取 PSS。一个 worker 的资源统计必须包含其子进程，
否则模型编译、数据加载或作业库子进程会被漏掉。

### NPU 内存

周期性读取 `npu-smi info`，按物理卡和 PID 保存 HBM 使用。报告：

- 单个正式 worker 峰值；
- 单卡所有正式 worker 峰值总和；
- 整个实验阶段的设备峰值；
- 是否存在 CPU worker 意外初始化 NPU 上下文。

计时区内采样器应独立运行，且采样频率在 CPU/NPU 间一致。先测量采样器自身开销，避免
高频系统调用扭曲短算子测试。

## 重复实验与统计

每个算法/问题/设备/代码阶段至少运行 20 个独立种子。保存每次原始结果，再报告中位数、
均值、标准差、四分位距和 95% 置信区间。质量比较可使用配对非参数检验并进行多重比较
校正；时间比较同时报告单次延迟和单位 FE 吞吐。

不能只保留聚合均值，因为异常种子、退化可行率和长尾运行时间只有原始重复数据才能定位。

## 可视化输出

`ascendmoea.plotting` 提供目标空间、决策空间和指标曲线的 Plotly 图对象。出版级输出应遵守：

- 每个文件只包含一张图，不组合多个子图；
- 字体使用 Times New Roman；
- PNG 至少 300 PPI；
- PDF 通过支持矢量输出的渲染器生成，并检查 PDF 内元素不是整页位图；
- 每张图保留生成脚本、数据哈希和图注元数据。

```python
from ascendmoea.plotting import draw_metric_curve

figure = draw_metric_curve(fes, values, "IGD")
figure.write_html("igd_curve.html")
figure.write_image("igd_curve.pdf")
figure.write_image("igd_curve.png", scale=4)
```

静态 `write_image` 需要安装兼容的 Kaleido。导出后应逐张打开检查字体、坐标范围、图例、
遮挡和空白内容。
