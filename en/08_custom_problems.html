Custom Problem Development#

Minimal Implementation#

Custom problems inherit from Problem, specify dimensionality and boundaries, and define batched objective evaluations:

import torch

from ascendmoea import Problem, register_problem

@register_problem(name="BiSphere")
class BiSphere(Problem):
    """Two-objective sphere problem with separated optima."""

    name = "BiSphere"

    def __init__(self, n=100, d=10, max_fe=10_000):
        super().__init__(n=n, m=2, d=d, max_fe=max_fe)

    def setting(self):
        self.lower = torch.full((self.D,), -5.0, dtype=self.dtype, device=self.device)
        self.upper = torch.full((self.D,), 5.0, dtype=self.dtype, device=self.device)

    def cal_obj(self, x):
        return torch.column_stack(
            [
                torch.sum(x.square(), dim=1),
                torch.sum((x - 2.0).square(), dim=1),
            ]
        )

Registered classes can be instantiated dynamically via configuration strings:

from ascendmoea import create_problem

problem = create_problem("BiSphere", n=200, d=50, max_fe=50_000)

Batched Tensor Shape Contract#

For an input batch x.shape == (B, D):

  • cal_obj(x) must return a tensor of shape (B, M).

  • cal_con(x) must return a tensor of shape (B, C).

  • Single-objective or single-constraint formulations must explicitly retain the second rank dimension.

  • Unconstrained problems default to a single column of zeros generated by the base class.

  • Returned tensors must share the device placement and compatible floating-point precision of x.

Avoid iterative evaluation patterns:

# Anti-pattern: per-individual Python loop and host scalar extraction.
values = [float(objective(row.cpu().numpy())) for row in x]

Formulate evaluations via vectorized tensor broadcasting, reductions, masking, slicing, or batched linear algebra operations.

Constrained Problem Formulations#

class ConstrainedBiSphere(BiSphere):
    def cal_con(self, x):
        radius_violation = torch.sum(x.square(), dim=1) - 16.0
        linear_violation = x[:, 0] + x[:, 1] - 1.0
        return torch.column_stack([radius_violation, linear_violation])

Feasibility is defined as non-positive values across all columns (\(\le 0\)). Equality constraints \(h(x) = 0\) must be converted into bounded tolerance inequalities \(\vert{}h(x)\vert{} - \epsilon \le 0\), logging the parameter \(\epsilon\) in experimental protocol metadata.

Mixed Variable Encodings#

Configure the variable representation by defining an integer tensor of length \(D\) in setting:

self.encoding = torch.tensor(
    [1, 1, 2, 2, 4, 4], dtype=torch.long, device=self.device
)

Decision bounds, encoding vectors, and variable operations must remain strictly aligned. If candidate solutions require domain-specific repair transformations, override the public cal_dec hook:

def cal_dec(self, x):
    repaired = x.clone()
    repaired[:, :2] = repaired[:, :2] / repaired[:, :2].sum(dim=1, keepdim=True)
    return repaired

The cal_dec method must preserve input tensor shape [N, D]. Never modify decision variables implicitly inside cal_obj without updating the decision tensor, as the recorded population will fail to reflect the actual evaluated parameters.

Reference Pareto Fronts#

Override get_optimum(n) to return an [K, M] matrix of true Pareto-optimal objective vectors:

def get_optimum(self, n=1000):
    t = torch.linspace(0, 1, n, dtype=self.dtype, device=self.device)
    return torch.column_stack([t, 1 - torch.sqrt(t)])

To support front plotting, override get_pf(). For multimodal problems, provide decision-space Pareto sets through independent data modules or standalone generation routines, explicitly defining decision-space equivalence criteria.

Data-Driven Problem Resources#

Static problem datasets must be placed in the package resource tree and loaded via importlib.resources or standard resource loaders. The problem constructor must manage immutable parameters, leaving the evaluation routine restricted to batched tensor math. Transpose loaded constants to the problem's active dtype and device, ensuring cached buffers migrate correctly when problem.device changes.

Execution Example#

problem = BiSphere(n=8, d=5, max_fe=16)
population = problem.initialization()
print(population.decs.shape)
print(population.objs.shape)
print(population.cons.shape)
print(problem.FE)

Output tensor shapes correspond to [8, 5], [8, 2], and [8, C] (where \(C\) is the constraint column dimension); FE evaluates to 8. The resulting problem instance can be passed directly to optimize().
