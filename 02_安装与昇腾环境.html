CPU 安装#

在项目根目录创建隔离环境并安装：

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .

Windows PowerShell 激活命令为：

.\.venv\Scripts\Activate.ps1
python -m pip install .

昇腾安装#

设备驱动、固件、CANN、PyTorch 和 torch_npu 必须按华为兼容矩阵安装。已有运行环境 时，推荐先激活 Python 环境，再加载两个 CANN 环境脚本：

source /path/to/your/python/environment/bin/activate
source /usr/local/Ascend/nnrt/set_env.sh
source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd /path/to/AscendMOEA
python -m pip install -e . --no-deps

--no-deps 可以防止通用 PyPI 依赖解析替换服务器上已经匹配的设备版 PyTorch。 使用 uv 管理该环境时可执行：

uv pip install -e /path/to/AscendMOEA --no-deps

安装验证#

python - <<'PY'
import torch
import ascendmoea

print("version", ascendmoea.__version__)
print("torch", torch.__version__)
print("npu_available", ascendmoea.npu_is_available())
print("algorithms", len(ascendmoea.list_algorithms()))
print("problems", len(ascendmoea.list_problems()))
PY

预期内置数量为 18 个算法和 155 个问题。NPU 环境还应执行：

npu-smi info
python examples/quick_start.py
ASCEND_RT_VISIBLE_DEVICES=0 python examples/cpu_npu_timing.py

设备选择#

显式指定最可靠：

result = optimize(algorithm, problem, device="cpu", cpu_threads=8)
result = optimize(algorithm, problem, device="npu:0")

也可以设置 ASCENDMOEA_DEVICE=cpu 或 ASCENDMOEA_DEVICE=npu:0，再把 device 留为 None。正式实验应显式写入配置，避免环境变量造成不可见差异。

CPU 后端隔离#

库会在导入 PyTorch 之前设置：

TORCH_DEVICE_BACKEND_AUTOLOAD=0

这是为了防止纯 CPU worker 因环境中安装了 torch_npu 而自动初始化 NPU 上下文。 CPU 实验不应出现在 npu-smi 的进程列表中。需要 NPU 时，设备模块会按需导入后端。

线程设置#

cpu_threads 是单个实验进程内部的 PyTorch 计算线程数，不是并行重复次数。单次基准若 规定 CPU 8 线程，应传入 cpu_threads=8，并同时设置 BLAS/OpenMP 环境变量：

export OMP_NUM_THREADS=8
export MKL_NUM_THREADS=8
export OPENBLAS_NUM_THREADS=8

用 joblib 并行 16 个重复实验时，总线程需求约为 16 * 8，必须根据物理核心和 NUMA 拓扑控制并发，避免过度订阅。

常见安装错误#

  • No module named torch_npu：CPU 仍可运行；NPU 需安装匹配后端。

  • NPU 不可用但 npu-smi 正常：检查 CANN 环境脚本、版本组合和进程可见卡设置。

  • 安装时替换了 PyTorch：重新恢复设备版环境，并用 --no-deps 安装本项目。

  • 找不到实际问题 MAT 文件：确认使用 wheel 或正常安装，而不是只复制单个 .py 文件。

  • CPU worker 占用 NPU0：确认库在任何 torch 导入之前加载，且未由其他模块提前导入 torch_npu。
