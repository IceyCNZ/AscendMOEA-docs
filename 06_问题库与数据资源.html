问题库与数据资源#

问题体系#

发布版注册 155 个问题，覆盖解析基准、约束、多模态、稀疏大规模和实际应用。完整名称 应通过代码查询，以安装版本为准：

from ascendmoea import list_problems

for name in list_problems():
    print(name)

实际与组合问题#

实际问题包括 RWMOP1 至 RWMOP10，以及 MONRP、MOTSP、MPDMP、RLP、UECLP、 application、mQAP、map 等任务。稀疏实际问题包括 Sparse_KP、Sparse_PM、 Sparse_PO 和 Sparse_SR。

这类问题可能具有以下特点：

  • 构造函数从包资源读取 MAT 数据；

  • 决策变量可能是整数、标签、二进制或排列编码；

  • 可用的维数和目标数受数据实例限制；

  • 单次评价可能包含距离矩阵、图结构或组合约束。

使用前应读取具体类的 docstring 和构造参数，不要把解析函数的 d 参数规则直接套用到 实际问题。

直接导入与注册名构造#

合法 Python 标识符会在 ascendmoea.problems 中直接导出：

from ascendmoea.problems import DTLZ2, LIRCMOP5, RWMOP3

p1 = DTLZ2(n=100, m=3, d=12, max_fe=10_000)
p2 = LIRCMOP5(n=100, max_fe=10_000)
p3 = RWMOP3(n=100, max_fe=10_000)

任何注册名都可通过统一接口构造：

from ascendmoea import create_problem

problem = create_problem("SYM_PART_simple", n=100, max_fe=10_000)

对于含空格、连字符或其他非标识符的名称，必须使用统一构造接口。

编码约定#

Problem.encoding 中每个变量的编码值为：

值

编码

1

实数

2

整数

3

标签

4

二进制

5

排列

基础初始化器会按编码批量生成决策，并对整数、标签和二进制执行与参考语义一致的舍入与 边界修复。用户算法调用变异算子时，应选择支持对应编码的入口。

参考数据与指标#

problem.optimum 是延迟生成并缓存的目标空间参考点，problem.pf 是可选的绘图表示。 内置多模态问题还通过 problem.ps 提供决策空间参考 Pareto 集；其他问题不保证存在 该属性。

reference_objectives = problem.optimum
drawable_front = problem.pf
reference_decisions = problem.ps  # Multimodal problems only.

三者用途不同：目标指标使用 optimum，决策指标使用 ps，而 pf 可能只是曲线、网格 或 None。自定义多模态问题若不提供 ps，应独立生成参考集并随实验数据固化。

包资源访问#

数据文件位于安装包的 ascendmoea/vendor 资源树，由问题类按包位置解析。安装 wheel 后可用标准库查看其中的数据文件：

python - <<'PY'
from importlib.resources import files

root = files("ascendmoea").joinpath("vendor")
print(root)
PY

自定义问题不要使用依赖当前目录的相对路径，也不要把服务器绝对路径写入资源定位逻辑。
